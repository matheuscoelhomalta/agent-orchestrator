# Native cancellation and runner-loss recovery check

2026-09-26: PASS for the bounded Codex behaviors below. Four paid native turns used the installed `agent-orchestrator` CLI with existing native authentication, isolated temporary state, a text-only read-only task, and a fixture directory containing one sentinel file. Each turn was bounded at 180 seconds. No source, configuration, permission policy, or real repository fixture was changed.

1. Cancellation was requested after native text had actually streamed: the first delta was event 6, cancellation event 58, and canonical settlement event 66. The interrupted output contained 91 characters. Execution and task state both settled `cancelled`. A fresh runner resumed the identical native session, recalled `recovery-4829`, and completed; independent marker/identity checks preceded acceptance.
2. A separate runner was deliberately killed after `prompt_dispatched` event 4. Ownership was established from the live runner command containing the unique state directory, worker ID, and current request ID, plus the adapter's recorded launch ID and live parent-child tree. Seven processes were captured in that tree. Immediately before signaling, PID, process start time, and full command still matched. Only the owned runner received SIGKILL and owned adapter received SIGTERM; the remaining captured descendants exited. All seven captured process identities were absent afterward. This did not use saved PIDs as authority.
3. Status reconciled the lost runner to `unknown`. A reply returned `INVALID_STATE` without dispatching a new turn. The sentinel file's bytes and directory membership were unchanged. Explicit resolution naming the current unknown request produced settled `failed`; a subsequent reply resumed the same native session and recalled `crash-5931`. The native session stores remained usable without repair or a fresh session. The response also completed the original text-only arithmetic objective, which remains part of the worker's recorded objective on replies. Acceptance verified session continuity and marker recall; it is not an independent audit of every arithmetic intermediate.
4. Both created workers ended `accepted`, `runnerDone: true`, with no runner present. All ten adapter launches were accounted for: nine recorded matching exits, and the crash-injected launch had verified manual cleanup and absence. All launch PIDs were absent in the final process audit. No live worker command referenced the unique temporary state directory.

The compact sanitized evidence is in `../evidence/native-recovery-check/checks.json`. It records assertions, IDs, request/event sequence metadata, settlement, launch accounting, and verified cleanup signals. `protocol.mjs` records the exact CLI command construction and controlled prompts; `finalize.mjs` records the independent final paginated event/process audit. The final audit paginated all 2,048 crash-worker events, rather than mistaking the first 1,000-event page for the complete log. No thought chunks, tool payloads, credentials, or native conversation files were copied into repository evidence.

Limits: this proves the observed Codex text-only cancellation/recovery paths with intact native stores. It does not prove cancellation during a side-effecting tool, automatic orphan cleanup after arbitrary crashes, recovery with damaged native stores, Claude recovery, permission approval, OS sandbox enforcement, or absence of effects outside the controlled fixture. The deliberate crash required manual cleanup and explicit resolution; the lost turn did not fabricate a canonical result. Temporary native state remains local as the harness's own session storage.
